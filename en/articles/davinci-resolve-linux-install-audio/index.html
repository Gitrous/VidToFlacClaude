DaVinci Resolve is arguably the best professional video editor available on Linux — and it is completely free. But there is a catch nobody warns you about: it is very common for video files to import with no audio. It is not a bug. It is a licensing problem with a simple, free solution. This guide covers the two steps every new user needs: installing DaVinci Resolve, and fixing the audio.

Why use DaVinci Resolve on Linux

DaVinci Resolve on Linux offers everything the Windows or macOS version does, at no extra cost:

  • A complete video editor — cutting, multicam, transitions, titles.
  • Professional colour grading — the same engine Hollywood productions use.
  • Fairlight — a built-in audio DAW with up to 2,000 tracks.
  • Fusion — node-based VFX compositing and motion graphics.
  • Watermark-free export — unlike other free tools.

Linux is also where DaVinci Resolve performs best on machines with AMD GPUs, because AMD's open-source drivers (AMDGPU-PRO) tend to hit fewer compatibility problems than on Windows. Plenty of professional colourists and editors work exclusively on Linux for that reason.

Pop!_OS is the distribution to pick if you are starting from scratch. System76, who make it, keep GPU drivers up to date by default, and the multimedia workflow is better tuned than on stock Ubuntu.

Installing on Ubuntu and Pop!_OS

The process is the same for Ubuntu 22.04, 24.04 and Pop!_OS. There is no official APT repository — the installer is a .run script you download from Blackmagic.

1
Download the installer from Blackmagic Design

Go to blackmagicdesign.com → Support → Downloads → DaVinci Resolve. Choose "Linux" and download the latest release. You will have to give an email address; it is free. The file is a .zip of roughly 3–4 GB.

2
Install the required dependencies

Open a terminal and install the libraries the installer needs:

sudo apt update
sudo apt install libglib2.0-0 libgl1-mesa-glx libglu1-mesa libssl3 fuse

On Ubuntu 24.04, libssl3 may already be installed. If the command fails on one library, try again without it.

3
Extract the ZIP and run the installer 
cd ~/Downloads
unzip DaVinci_Resolve_XX_Linux.zip
chmod +x DaVinci_Resolve_XX_Linux.run
sudo ./DaVinci_Resolve_XX_Linux.run

Replace XX with the version number you downloaded. The installer shows a graphical interface, so you need an active desktop session. Accept the licence and follow the steps.

4
Check your GPU drivers

If you have an NVIDIA GPU, check that the proprietary drivers are installed:

nvidia-smi

If the command fails, install them from Settings → Additional Software → Drivers on Ubuntu, or from the Pop!_OS driver app. The open-source nouveau drivers are not sufficient.

For AMD GPUs, the open-source AMDGPU drivers ship with the Ubuntu 22.04+ kernel. On machines with an AMD RX 5000 or later, consider installing amdgpu-install for better performance.

5
Launch DaVinci Resolve

Look for "DaVinci Resolve" in the application menu, or run it from the terminal:

/opt/resolve/bin/resolve

Installing on Fedora

Fedora uses RPM rather than DEB, but Blackmagic's .run installer works just the same. The dependencies differ:

sudo dnf install libglib2.0 mesa-libGLU fuse fuse-libs openssl

Then extract the ZIP and run the .run file with sudo, exactly as on Ubuntu. On Fedora 40+, if the installer fails on missing libraries, the easiest route is the unofficial community package:

# Add the RPM Fusion repo (needed for the package)
sudo dnf install https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm
# Then look for davinci-resolve in COPR, or follow the Fedora wiki thread

The official Fedora wiki keeps up-to-date instructions for each release.

First launch and basic setup

The first time you open DaVinci Resolve you land on the Project Manager. Before creating your first project, set a couple of things:

Set the cache drive

Go to DaVinci Resolve → Preferences → System → Media Storage. Point the working cache at a fast SSD with free space. This makes a real difference to performance when editing at high resolution.

Check the detected GPU

Under Preferences → System → Memory and GPU, check that DaVinci Resolve can see your GPU. If it reports no compatible GPU, the problem is drivers — go back to step 4 of the installation.

Create your first project

Click "New Project", give it a name and pick the resolution of your footage (1080p, 4K and so on). You can change it later under File → Project Settings.

Before you import anything: read the next section on the audio problem. A good share of the files you are likely to have — iPhone recordings, OBS captures, GoPro and mirrorless footage — use audio codecs Resolve cannot decode on Linux, and import silent. It is the most common DaVinci Resolve problem on Linux, and it takes two minutes to fix.

The audio problem: why it is so common on Linux

Critical problem · very common on Linux

DaVinci Resolve imports the video, but the audio is silent

You import your OBS capture, your iPhone video or your mirrorless clip. It lands on the timeline and looks perfect… but there is no audio. The waveform is flat. Or there is no audio track at all.

This happens with practically any file recorded on consumer hardware:

  • OBS Studio recordings (MKV or MP4 with AAC audio)
  • Video from iPhone, Samsung, Pixel and any other smartphone
  • Clips from GoPro, DJI and Insta360
  • MOV files from Sony, Canon, Fujifilm and Nikon cameras
  • Videos downloaded from YouTube (WebM with Opus audio)
  • Screen recordings from QuickTime, Bandicam and Shadowplay

Why it happens: the licensing problem

The most common audio codecs — AAC, MP3, AC-3 (Dolby Digital) — are patent-protected. Companies shipping them in their products have to pay royalties to the patent holders: Via Licensing, Fraunhofer, Dolby and others.

On Windows and macOS the operating system already carries those licences transparently, so any application can decode AAC without paying anything extra. Linux has no centralised licensing arrangement: each company has to pay for and ship the decoders itself.

Blackmagic Design chose not to include those decoders in the free Linux build of DaVinci Resolve. It is neither a bug nor an oversight: it is a business decision. The practical result is that DaVinci Resolve on Linux cannot read AAC, MP3 or E-AC-3 audio.

How to avoid the problem at source

Once you know about the problem, you can set your workflow up so it never recurs:

OBS Studio: record straight to FLAC

OBS 27 and later can record MKV with FLAC audio. Go to Settings → Output → Recording tab and set:

  • Recording format: MKV
  • Audio encoder: FLAC

With that configuration, all your OBS clips work directly in DaVinci Resolve on Linux with no conversion step.

Phone or camera: batch-convert before importing

If you shoot on an iPhone, an Android phone or a mirrorless camera, the easiest workflow is to use VidToFLAC in batch: drop in the whole folder of clips, convert, and everything is ready to import into DaVinci Resolve.

Footage in an editing format (ProRes, DNxHR)

If your camera records ProRes (Apple, some Canon models) or DNxHR, that footage carries PCM audio, which DaVinci Resolve on Linux handles without trouble. You only need to convert when the audio is AAC, MP3 or Opus.

Performance tips on Linux

With the right settings, DaVinci Resolve on Linux can perform as well as or better than on Windows:

Use proxies for H.264/H.265 footage

H.264 and H.265 are inter-frame codecs: each frame depends on the ones before it, which makes real-time editing expensive for the CPU. In DaVinci Resolve, go to Playback → Generate Optimized Media to create low-resolution copies used only while editing. The final render still uses the originals.

Turn down playback quality

In the bottom-right corner of the viewer, the playback quality menu lets you drop to half or quarter resolution while editing, without affecting the final render. On mid-range GPUs this eliminates stuttering when playing back 4K.

Optimised video cache

Turn on Playback → Render Cache → Timeline. DaVinci Resolve pre-computes and stores the processed frames. The first pass is slower, but the second plays smoothly.

GPU vs CPU rendering

Under Preferences → System → Memory and GPU, make sure the processing mode is GPU rather than CPU. If your GPU is NVIDIA, select CUDA instead of OpenCL — CUDA generally performs better in DaVinci Resolve.

Increase the allocated RAM

In the same preferences pane, adjust the RAM allocated to DaVinci Resolve. With 32 GB installed, allocate between 16 and 24 GB. This reduces bottlenecks when processing high-resolution clips.

Frequently asked questions

Does DaVinci Resolve work well on Linux?

Yes, very well. DaVinci Resolve on Linux offers all the editing, colour, audio and VFX functionality of the Windows or macOS version. The one significant problem is audio codec support: the free version decodes neither AAC nor MP3. VidToFLAC solves that by converting the audio to FLAC before you import.

Why does DaVinci Resolve play no audio on Linux?

Blackmagic Design does not include the AAC, MP3 and other codec patent licences in the Linux build. On Windows and macOS the operating system already carries them; on Linux it does not. The fix is to convert the audio to FLAC, which is supported, before importing the clips.

Does DaVinci Resolve Studio fix the audio problem on Linux?

Partly. Studio ships more decoders on Linux, but E-AC-3 and some AAC profiles still will not work. The most reliable fix, and a free one, is to convert the audio to FLAC with VidToFLAC — it works with the free version, no Studio purchase needed. Read more in DaVinci Resolve free vs Studio.

Do I need to compile FFmpeg or install codecs separately?

Not for editing in DaVinci Resolve — installing a system FFmpeg with AAC support achieves nothing, because DaVinci Resolve uses its own internal decoders. The only approach that works is to convert the files before importing them, either with VidToFLAC or with FFmpeg in the terminal using -c:a flac.

Does DaVinci Resolve work on Arch Linux or Manjaro?

Yes. There is a community-maintained AUR package (davinci-resolve) that makes installation straightforward on Arch, Manjaro and EndeavourOS. It is unofficial, but it works well. The AAC audio problem applies exactly as it does on Ubuntu.

My OBS clips have no audio in DaVinci Resolve on Linux — why?

Because OBS records AAC by default, and DaVinci Resolve on Linux cannot read AAC. Two options: (1) convert the clips with VidToFLAC before importing, or (2) set OBS to record FLAC directly: Settings → Output → Recording → Format: MKV, Audio encoder: FLAC. See the full guide at DaVinci Resolve not importing OBS audio.
