OBS with two audio tracks: why DaVinci Resolve only gets one

If you record with OBS and keep the game on one track and your microphone on another, there is one detail worth knowing before you convert the file: the conversion keeps a single track and throws the rest away. It gives no warning, and on the DaVinci Resolve timeline everything looks fine until you go looking for your voice and it is not there. I measured it with a two-track file so I could say exactly what stays and what disappears.

What happens, in one sentence

The command VidToFLAC runs is ffmpeg -i input -c:v copy -c:a flac output.mkv, and it has no -map. Without that option FFmpeg applies its default selection: one video stream, one audio stream, everything else left out. With a single-track file — most files — you never notice. With a multitrack OBS recording, half the recording is gone.

The practical summary: if your file has one audio track, the tool does what you expect. If it has two or more and you want them all, convert it with FFmpeg in the terminal adding -map 0:v -map 0:a. The exact command is further down.

Why OBS records several tracks

Under Settings → Output → Recording, OBS has a row of checkboxes labelled "Audio Track". Each box you tick adds an independent track to the file, and in the mixer you decide which source goes to which. The usual split for someone recording gameplay is: track 1 with the full mix, track 2 with the game audio and track 3 with the microphone.

There is a very specific reason for it: while editing you want to pull the game down without pulling your voice down with it, or clean up a noise on the mic without touching the music. With everything mixed into one track that is no longer possible. So someone recording multitrack does not want "the good track" — they want all of them.

The price is that from then on, any tool that is not built for multitrack may keep just one, and that discard almost never shows up on screen.

The test: two tracks in, one out

To measure it I used FFmpeg to build a file shaped like what OBS produces: H.264 video and two stereo AAC tracks at 160 kbps, with different content on each so they could be told apart afterwards.

ffprobe -v error -show_entries stream=index,codec_type,codec_name -of csv=p=0 obs.mp4 0,video,h264 1,audio,aac 2,audio,aac

That file went through the same command the tool issues when converting a video. The result:

ffprobe -v error -show_entries stream=index,codec_type,codec_name -of csv=p=0 output.mkv 0,video,h264 1,audio,flac

Two tracks in, one out. The file takes 2,546 KB instead of the 3,402 KB it takes when both are kept, and there is no error message anywhere: FFmpeg considers that it did exactly what it was asked, because it did.

Which of the two survives

FFmpeg does not take the first one by position — it takes the one it considers "best": first it looks at the channel count, then at the bitrate, and only on a tie does it keep the one that appears earlier in the file. Since both test tracks were stereo at the same bitrate, the first one won.

To confirm that without trusting the theory, I decoded all three signals — the two input tracks and the output — and compared them sample by sample:

Comparison Maximum difference Conclusion
Output against track 11.19 × 10⁻⁷Same signal
Output against track 20.92Unrelated

That 1.19 × 10⁻⁷ is one 24-bit quantisation step: track 1 arrives whole, merely rounded when stored as FLAC. The 0.92 figure is simply a different signal.

What that means in practice depends on how your OBS tracks are laid out. If track 1 is the full mix, you got lucky: what reaches the editor has everything in it, even if you can no longer separate it. If track 1 is the game and the microphone is on track 2, what reaches the editor is the session without your voice.

The command that keeps them all

With FFmpeg installed on your system, you just have to tell it explicitly which streams you want in the output:

ffmpeg -i obs.mp4 -map 0:v -map 0:a -c:v copy -c:a flac output.mkv

-map 0:v takes every video stream from the first input and -map 0:a every audio stream. The video is copied untouched, exactly as the tool does it, and each audio track is encoded to FLAC separately. In the test the output went from one track to two, and the file from 2,546 to 3,402 KB.

For a whole folder of recordings:

for f in *.mp4; do ffmpeg -i "$f" -map 0:v -map 0:a -c:v copy -c:a flac "${f%.mp4}.mkv"; done

The container has to be MKV. MP4 does allow several audio tracks, but FLAC inside MP4 is still experimental in FFmpeg and causes more problems than it solves; MKV holds as many FLAC tracks as you need without any odd flags. If you have never used FFmpeg in a terminal, the guide on converting video with FFmpeg without installing anything covers the rest of the syntax.

And Resolve may still show you a single track

Here is the part no guide mentions, and it only turns up once you drag the real files into the program. An MKV with two FLAC tracks inside — confirmed with ffprobe, no room for doubt — imported into DaVinci Resolve Studio 21.0.4 on Ubuntu with a single audio track on the timeline. The command had done its job; the editor was not showing the result.

The odd thing is that it does not always happen. I generated thirteen variants of the same clip, changing one thing at a time — the default-track flag, the track names, 16 against 24 bits, 44.1 against 48 kHz, the resolution, the duration, the tags inherited from an MP4 source — and some opened two tracks while others opened one, with none of those properties explaining the difference. With every one of them ruled out on its own, the honest conclusion is that it is not in the file: it depends on the state of Resolve, which stores a clip's audio attributes the first time it reads it.

What matters is that the audio was never lost. It is inside the file, and Resolve can see it:

  1. Right-click the clip in the Media Pool.
  2. Clip Attributes… → Audio tab.
  3. Under Format, choose how many tracks you want and of what kind: two mono tracks, in the usual OBS case of game and microphone.
  4. Under Source Channel for each track, assign Embedded Channel 1 and Embedded Channel 2.

Once you accept, the clip carries the two separate tracks on the timeline, each with its own volume and effects, which is the whole point of recording multitrack. Do it before dragging it in: if it is already on the timeline, remove it, change the attributes and drag it again.

Put another way: if you convert with -map and see a single track when you drag the file in, do not convert it again. The file is fine. Clip Attributes is what needs changing.

How to see how many tracks you have

Before converting anything, look at what is inside. With FFmpeg installed:

ffprobe -v error -show_entries stream=index,codec_type,codec_name -of csv=p=0 recording.mp4

Each line is one stream. If more than one says audio, your file is multitrack. Without FFmpeg, the same information shows up in MediaInfo. In DaVinci Resolve, do not trust how many tracks you see on the timeline — it can show one while the file holds two, as explained above: check it in Clip Attributes → Audio, where Source Channel lists the channels the file actually carries.

How to avoid it from OBS

If you are not going to mix separately, leave only track 1 ticked under Settings → Output → Recording and make sure every source in the mixer is routed to it. That is a smaller file, it converts in the tool without touching a terminal, and it imports anywhere without surprises.

If you are going to mix separately, keep the tracks, but also send the full mix to track 1. That way, if one day you convert the file with a tool that keeps only one, what survives is the complete mix rather than half the recording.

And there is a third option that skips the problem entirely: record in MKV from the start. Under Settings → Output → Recording → Recording Format, choose mkv instead of mp4. You can then use FLAC as the recording's audio codec, which leaves nothing to convert afterwards. It is also safer if something crashes: an MP4 cut off mid-write is corrupt, an MKV is not.

Frequently asked questions

Does VidToFLAC keep both audio tracks from an OBS recording?

No. The command the tool runs has no -map, so FFmpeg picks a single audio track and discards the rest. In the test with a two-track AAC MP4, the output had one FLAC track, identical to the first one in the original. If you need both, convert with FFmpeg in the terminal using -map.

Which track survives when there are several?

The one FFmpeg considers best: with equal channel count and bitrate, the first one in the file. In the measurement, the output audio matched track 1 sample for sample and had no relation to track 2. In a typical OBS recording track 1 is the mix or the game sound, and the microphone sits on track 2.

Which FFmpeg command keeps every track when converting to FLAC?

ffmpeg -i input.mp4 -map 0:v -map 0:a -c:v copy -c:a flac output.mkv. The -map 0:a selects every audio track in the input instead of letting FFmpeg choose one. In the test, the output went from one to two FLAC tracks and the file grew from 2,546 to 3,402 KB.

How do I know how many audio tracks my recording has?

Run ffprobe -v error -show_entries stream=index,codec_type,codec_name -of csv=p=0 file.mp4 to list every stream in the file. In OBS, the number of tracks is the number of boxes ticked under Settings → Output → Recording → Audio Track.

Is it better to record a single mixed track in OBS?

It depends on whether you will want to duck the game under your voice while editing. If the answer is yes, record separate tracks and convert them with -map. If you will never touch them separately, one track simplifies the whole workflow: a smaller file, a conversion the tool handles on its own, and an import that works in any editor.
